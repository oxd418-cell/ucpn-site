# Сайт UCPN

Двомовний (UA / EN) сайт: програма подій, публікації, архів за роками, сторінки «Про нас» і «Контакти».
Команда додає й редагує все через CMS на `/admin/`, без коду.

> Приклади подій, публікацій і фото взято з макетів. Перед запуском замініть їх справжніми.

## Перед запуском: що замінити

1. `src/data/site.yml` → `url`: справжня адреса сайту (потрібна для SEO, sitemap і соцмереж). Зараз `https://example.org`.
2. `src/admin/config.yml` → `repo: OWNER/REPO` на ваш репозиторій GitHub; `site_url` і `display_url` на справжню адресу.
3. У CMS (`Налаштування → Сайт`) заповніть пошту, Instagram, адресу, юридичну інформацію. Порожні поля на сайті не показуються.
4. У CMS (`Налаштування → Партнери`) додайте логотипи (SVG або PNG з прозорим тлом) і посилання.
5. Сторінка «Про нас»: `src/content/pages/about.uk.md` і `about.en.md` (або через CMS → Сторінки).
6. Посилання на Instagram кураторів і художників: у CMS, поле «Instagram».

## Запуск на комп'ютері

Потрібен Node.js 18 або новіший.

```
npm install
npm run build     # збирає сайт у папку dist/
npm start         # збирає і відкриває http://localhost:8080
```

## Публікація (GitHub Pages, безкоштовно)

1. Створіть репозиторій на GitHub і завантажте туди цю папку (гілка `main`).
2. Репозиторій → Settings → Pages → Source: **GitHub Actions**.
3. Готовий розклад уже є: `.github/workflows/deploy.yml`. Він збирає й публікує сайт при кожній зміні та щоночі.
4. Адреса буде `https://власник.github.io/репозиторій/`. У цьому разі в `src/data/site.yml` вкажіть `url: https://власник.github.io` і `basePath: /репозиторій`.
5. Власний домен: Settings → Pages → Custom domain. Після підключення поставте `basePath: ""` і `url: https://ваш-домен`.

Cloudflare Pages або Netlify теж підходять: команда збірки `npm install && npm run build`, папка результату `dist`. Файли `_headers` і `_redirects` уже в проєкті. Щоденну перебудову там налаштовують через Deploy Hook, який викликає той самий розклад GitHub Actions.

## Як команда додає подію (CMS)

1. Відкрити `адреса-сайту/admin/` і увійти через GitHub.
2. **Події → New**. Заповнити:
   - «Адреса сторінки»: латиницею, наприклад `kinder-album`. Це адреса події назавжди, після публікації не змінюйте.
   - Дату, категорію, назву, опис, фото. Українську й англійську версії заповнюють на двох вкладках.
3. Зберегти. За хвилину сайт оновиться.

Вхід у CMS: найпростіше увійти через персональний токен GitHub (Settings → Developer settings → Fine-grained tokens, доступ до цього репозиторію, право Contents: Read and write). Вхід кнопкою GitHub потребує окремого невеликого OAuth-сервісу. Актуальні кроки дивіться в документації Sveltia CMS (https://github.com/sveltia/sveltia-cms).

### Після події

Відкрийте ту саму подію в CMS і додайте:
- **Результати події**: текст;
- **Документація: фото після події**: фотографії;
- **Посилання на відео**.

Адреса сторінки не змінюється, нові блоки з'являються на ній самі.

## Як подія переходить з «Майбутніх» у «Минулі»

Це відбувається автоматично, за київською датою:
- у браузері: скрипт на сторінці щоразу порівнює дату події з сьогоднішньою;
- на сервері: щоночі після півночі сайт перебудовується (`deploy.yml`), тож без скрипта теж усе правильно.

Подія вважається майбутньою до кінця дня завершення (`Дата завершення`, а якщо її немає, `Дата початку`).

## Адреси сторінок

- `/uk/` і `/en/`: програма (Майбутні / Минулі, фільтр за категоріями без окремих сторінок)
- `/uk/events/назва/`, `/en/events/назва/`: подія
- `/uk/publications/`, `/en/publications/`: публікації; кожна має свою сторінку
- `/uk/archive/`, `/uk/archive/2026/`: архів за роками (роки з'являються самі)
- `/uk/about/`, `/uk/contact/`
- `/`: відкриває мову браузера. Між мовами перемикає «UA / EN» (ту саму сторінку).

## SEO, швидкість, доступність

- Для кожної сторінки: заголовок, опис, canonical, hreflang UA/EN, Open Graph, `sitemap.xml`, `robots.txt`; для подій ще структуровані дані Schema.org Event.
- Фото: при збірці автоматично створюються webp і jpg у чотирьох розмірах (до 1600 px), браузер бере підходящий. У CMS можна завантажувати фото без попереднього стиснення, але краще до 3000 px завширшки.
- Сайт читається й без JavaScript; скрипт лише перемикає вкладки, фільтри й галерею.
- Навігація з клавіатури, видимий фокус, «Перейти до змісту», опис фото для незрячих (поле «Опис фото»), адаптивна верстка.

## Що не перевірялося

- Вхід у CMS і збереження в GitHub не перевірені на справжньому репозиторії.
- Проєкт зібрано й переглянуто локально; після першої публікації пройдіться по сторінках обох мов.
